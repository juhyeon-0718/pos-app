# U-04b 주방 화면 명세 (태블릿·휴대폰)

상태: U-04(상태 정의·계약 확인)를 정주현 님 결정(주방은 태블릿과 휴대폰 사용, 밝은 테마, 지연 10분)에 맞춰 U-04b로 다시 썼다. 이전 1920×1080 벽걸이 모니터 기준과 "2m 거리" 기준은 폐기한다.
프로토타입: `prototype/kitchen-states.html`(상태 보기 바 또는 `?state=default|loading|empty|error|offline|busy|partial&tab=recv|cook`). 브라우저 폭을 줄이거나 늘려 두 레이아웃을 볼 수 있다. 캡처는 `screens/`.

## 폭 기준 (D-39, DESIGN.md 반응형)
폭 기준은 **768px 하나**다.
- **휴대폰(767px 이하, 기준 390):** 레인을 탭으로 나눠 한 레인만 보인다. 탭 "접수 n / 조리 중 n"(높이 56px, 위에 고정). 카드는 세로로 쌓는다.
- **태블릿 이상(768px 이상, 기준 1024×768):** 접수와 조리 중 두 레인을 나란히 둔다. 탭은 숨긴다. 상단 바에 현재 시각을 보인다.
- 미디어쿼리는 `@media (min-width: 768px) { /* 태블릿 이상 */ }` 하나.
- 글자·버튼 크기는 같은 토큰 이름을 쓰고 `:root` 미디어쿼리에서 값만 바꾼다.

| 토큰 | 휴대폰 | 태블릿 이상 | 쓰는 곳 |
|---|---|---|---|
| `--font-size-kitchen-title` | 36px | 48px | 테이블 번호 |
| `--font-size-kitchen-body` | 24px | 32px | 메뉴명·수량 |
| `--font-size-kitchen-meta` | 16px | 20px | 경과 시간·"번 테이블" |
| `--size-touch-kitchen` | 56px | 72px | 항목·일괄 버튼 높이 |

가독성 기준은 기기별로 다르다. 태블릿은 거치대에 두고 팔 길이(약 50~70cm)에서 읽고, 휴대폰은 한 손으로 잡고 읽는다. "2m 거리" 기준은 쓰지 않는다. 시안의 글자는 이 거리 기준으로 정한 설계값이며 실기기에서 읽어 보지 못했다. 현장 테스트에서 작다는 의견이 나오면 토큰 값만 올린다.

## 구성
- 상단 바: 로고, 화면 이름, 연결 상태(아이콘 + 글자, 예 "연결됨"), 태블릿 이상에서 현재 시각.
- 카드 하나는 위에서 아래로: 머리줄(테이블 번호 · 경과 시간 · 지연 배지), 항목 행들, 카드 일괄 버튼.
- 항목 행: 한 줄에 이름·수량, 그 아래 전체 너비 버튼. 휴대폰과 태블릿이 같은 구조라 이름이 잘리지 않는다(768px에서도 한 줄에 읽힘).
- 지연 표시: 접수 후 10분(확정) 이상이면 카드 테두리 `--color-warning` + "지연" 배지(아이콘 + 글자).
- 버튼 글자는 `--font-size-kitchen-meta`(휴대폰 16px, 태블릿 20px), 굵게. 높이는 `--size-touch-kitchen`.
- 긴 메뉴명은 2줄까지 보이고 말줄임(`word-break: keep-all`). 일반 텍스트로만 표시(D-24).

## 결정 1. 버튼은 항목 단위 + 카드 일괄 버튼
주방은 `PATCH /orders/{id}/status`를 쓸 수 없고 `PATCH /kitchen/items/{item_id}/status`(pending/cooking/done)만 쓴다. 주문 상태는 서버가 항목 상태로 자동 계산한다.
- 항목 행마다 버튼 하나: `pending` → "시작"(primary), `cooking` → "완료"(success). `done`이면 버튼 대신 "완료"(아이콘 + 글자)와 흐린 이름.
- 카드 하단 일괄 버튼은 같은 상태 항목이 2개 이상일 때만 나온다: 접수 레인 "전부 시작", 조리 중 레인 "전부 완료"(secondary). 프론트가 항목 PATCH를 항목 수만큼 호출한다.
- 레인(접수/조리 중)은 서버가 계산한 주문 상태 기준이다. 항목이 하나라도 `cooking`이면 주문은 조리 중 레인으로 옮겨진다.
- 이유: 한 요리가 먼저 나가는 일이 흔하고, 일괄만 있으면 먼저 끝난 요리를 표시할 수 없다. 일괄 버튼은 손이 바쁠 때 탭 수를 줄인다.

## 결정 2. 부분 실패
일괄 처리 중 일부 항목만 실패하면 성공한 항목은 그대로 두고 실패한 항목 행만 빨간 "다시 시도"(경고 아이콘 + 글자) 버튼으로 바꾼다. 화면 상단에 `role="alert"` 배너로 "7번 테이블: 3개 중 1개를 처리하지 못했습니다 / {메뉴명}만 다시 시도해 주세요. 나머지 2개는 처리됐습니다."를 남긴다. 배너는 자동으로 사라지지 않고 다시 시도가 성공하면 닫힌다. 휴대폰에서 실패 항목이 다른 탭에 있을 때를 위해 탭 숫자 옆에 실패 표시를 두지는 않고, 배너 문구에 테이블 번호를 넣어 찾을 수 있게 한다.

## 결정 3. 테마
밝은 테마로 통일한다(정주현 님 확인, D-39). 이전 주방 다크 팔레트(#111, #222)는 쓰지 않는다. 현장에서 눈부심 의견이 나오면 2차에서 토큰으로 다크 테마를 추가한다.

## 상태 정의
- **기본:** 태블릿은 두 레인, 휴대폰은 탭 + 한 레인. 접수 10분 이상 카드는 주황 테두리 + "지연" 배지.
- **로딩:** "주문을 불러오는 중"(스피너 + 글자) + 회색 스켈레톤 카드. 상단 연결 표시 "연결 중". 버튼 없음.
- **빈 상태:** 수저 아이콘 + "지금 들어온 주문이 없습니다" + "새 주문이 들어오면 이 화면에 바로 나타납니다." 레인 하나만 비었을 때는 레인 안에 "접수된 주문이 없습니다" / "조리 중인 주문이 없습니다".
- **오류(불러오기 실패):** 경고 아이콘 + "주문을 불러오지 못했습니다" + "네트워크를 확인하고 다시 시도해 주세요." + "다시 시도" 버튼. 상단 표시 "연결 안 됨"(빨강, 아이콘 + 글자).
- **연결 끊김(폴링 실패):** 마지막 데이터는 그대로 두고 경고 배너 "연결이 끊겼습니다. 다시 연결하는 중입니다." + "아래 주문은 18:41 기준이며 새 주문이 보이지 않을 수 있습니다. 버튼은 연결될 때까지 쓸 수 없습니다." + "다시 연결". 모든 버튼 비활성(`disabled`). 시각은 마지막 수신 시각을 쓴다.
- **처리 중(비활성):** 누른 항목 버튼은 스피너 + "처리 중"으로 비활성, 같은 카드 일괄 버튼도 비활성. 다른 카드는 계속 누를 수 있다. 응답이 오면 즉시 복구.
- **일부 항목 실패:** 위 결정 2.

## 완료 항목 표시
- 응답에 `done` 항목도 들어오므로 "완료"(체크 + 흐린 이름)는 그 주문이 주방 목록에 있는 동안 계속 보인다. 임시 표시는 없다.
- **모든 항목이 `done`인 주문은 주방 화면에서 숨긴다.** 서빙할 차례라 직원 화면 몫이다. 다음 폴링에서 카드가 사라진다.

## 휴대폰 탭 이동 안내
휴대폰에서 접수 탭의 "시작"을 누르면 서버가 주문을 조리 중으로 바꾸므로 카드가 접수 탭에서 사라진다. 이를 알리기 위해 화면 아래에 성공 토스트를 3초 보인다: "{n}번 테이블: 조리 중으로 옮겼습니다"(체크 아이콘 + 글자, 토스트 안에 "조리 중 보기" 버튼 없음). 탭 숫자는 즉시 바뀐다. 태블릿 이상은 두 레인이 같이 보이므로 토스트 없이 카드가 오른쪽 레인으로 옮겨진다. 토스트는 성공 안내 전용이고 오류는 배너로 남긴다.

## 실패 표시 해제 규칙
실패한 항목 행의 "다시 시도" 표시는 다음 폴링(5초) 응답에서 아래 중 하나가 되면 지운다. 응답이 유실됐지만 서버는 처리한 경우를 포함한다.
1. 그 항목의 상태가 목표 상태로 바뀌어 있을 때
2. 목표 상태가 `done`이고 그 주문의 모든 항목이 `done`이 되어 카드가 목록에서 사라졌을 때
사용자가 "다시 시도"를 눌러 성공해도 같은 방식으로 해제한다. 상단 부분 실패 배너는 해당 카드의 실패 행이 모두 없어지면 닫는다.

## 동선·접근성
- 터치 영역은 휴대폰 56px, 태블릿 72px(`--size-touch-kitchen`). 버튼 사이 간격 8px 이상(오터치 방지). 탭 56px.
- 포커스 링은 공통 토큰(2px). Tab 순서는 카드 순서대로.
- 연결 상태는 `role="status"`, 경고·실패 배너는 `role="alert"`. 탭은 `role="tablist"`/`tab`, 선택은 `aria-selected`.
- 상태는 항상 색 + 아이콘 + 글자.

## 데이터 (openapi.yaml 기준)
- Order: `id`, `table_no`, `status`, `created_at`, `items[]`(`menu_name`, `qty`, `item_status`, `table_no`). 화면에는 `table_id` 대신 `table_no`를 보여 준다. 경과 시간은 `created_at`에서 클라이언트가 계산한다.
- 주방 화면은 `GET /orders`를 `status=received`와 `status=cooking`으로 동시에 호출해 합쳐 레인을 나눈다(민준 님 확인: 주방 토큰으로 호출 가능, 계약 보완 불필요). `GET /kitchen/queue`는 쓰지 않는다.
- 경과 시간과 "지연" 배지는 주문의 `created_at`으로 계산한다.
- 갱신은 5초 폴링(D-30). SSE는 2차.
- 항목 처리 `PATCH /kitchen/items/{item_id}/status`. 응답 본문은 계약에 없으므로 쓰지 않고 다시 조회한다(B-16에서 계약 보완 예정).

## 계약 확인 결과 (민준 님 답변, 백엔드 코드 확인)
1. 일괄 처리는 항목 PATCH를 동시에 호출해도 된다(`Promise.allSettled`). 항목마다 별도 트랜잭션이고 주문 상태는 `received→cooking` 한 방향으로만 자동 변경돼 결과가 같다.
2. 같은 상태로 다시 보내도 200이다(멱등). 재시도는 안전하다.
3. 실제 응답은 `{item_id, status}`이고 404·409도 실제로 온다. 계약에는 이 셋이 없다. B-16에서 계약 보완 예정.

## 대비
본문 `--color-text-primary` on 흰색 16.1:1, "지연" `--color-warning-text` on `--color-warning-light` 7.41:1, 흰 글자 on 버튼 5.13~5.75:1. 직접 계산한 값이며 도구 검증 전.

## 완료 조건 (구현자)
1. 768px 미만은 탭 + 한 레인, 768px 이상은 두 레인. 미디어쿼리는 768px 하나이고 `/* 태블릿 이상 */` 주석을 단다.
2. 글자·버튼 크기는 토큰 이름을 바꾸지 않고 `:root`의 미디어쿼리에서 값만 바꾼다(위 표). 하드코딩 색·크기 없음.
3. 항목 단위 버튼과 일괄 버튼이 위 규칙대로 동작하고, 일괄 처리의 부분 실패에서 성공 항목은 유지된다. 실패 표시는 해제 규칙으로 지운다.
4. 연결 끊김에서 모든 버튼이 `disabled`이고 배너가 보인다.
5. 지연 기준 10분과 폴링 간격 5초는 각각 상수 하나로 둔다. 목록은 `GET /orders`의 `received`와 `cooking`을 동시에 호출해 합친다.
6. 모든 터치 요소는 휴대폰 56px, 태블릿 72px 이상(탭 포함).
7. 상태별 캡처: `screens/u04b-kitchen-{default,loading,empty,error,offline,busy,partial}-{tablet,phone}.png`, `u04b-kitchen-default-cook-phone.png`(휴대폰 조리 중 탭), `u04b-kitchen-default-768.png`(경계 폭).
