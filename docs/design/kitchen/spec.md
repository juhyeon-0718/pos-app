# U-04 주방 화면 명세

상태: 메인 화면(U-03) + 상태별 시안(U-04). 모니터 크기·지연 기준은 정주현 님 답변 대기.
프로토타입: `prototype/kitchen.html`(메인), `prototype/kitchen-states.html`(상태 보기 바 또는 `?state=default|loading|empty|error|offline|busy|partial`). 1920×1080 기준. 기준 기기: 주방 벽걸이·거치 모니터, 2m 거리, 장갑 낀 손.

## 구성
- 상단 바: 로고, 화면 이름, 연결 상태(아이콘 + 글자, 예: "연결됨"), 현재 시각.
- 두 레인: 접수(`received`) / 조리 중(`cooking`). 레인 제목에 건수.
- 주문 카드: 왼쪽 테이블 번호(72px)·경과 시간(32px), 오른쪽 메뉴명·수량(59px = 44pt), 하단 버튼 88px.
- 버튼은 항목 단위다(U-04 결정 1). 항목이 끝났으면 "완료"를 아이콘 + 글자로 표시하고 이름을 `--color-text-secondary`로 낮춘다.
- 지연 표시(제안): 접수 후 10분 경과 시 카드 테두리 `--color-warning` + "지연" 배지(아이콘 + 글자). 기준 분은 사장님 확인 후 확정.
- 긴 메뉴명은 2줄까지 보이고 말줄임. 텍스트는 일반 텍스트로만 표시(D-24).

## 사용 토큰
`--font-size-kitchen-title/body/meta`, `--size-touch-kitchen`, `--color-warning`, `--color-success`, `--color-success-hover`, `--color-primary`, `--border-default`, 공용 Button·Badge·Card(U-03 components).

## 데이터 (openapi.yaml 기준)
- Order: `id`, `table_no`, `status`, `created_at`, `items[]`(`menu_name`, `qty`, `item_status`, `table_no`). 화면에는 `table_id` 대신 `table_no`를 보여 준다.
- 항목 단위 조리 처리: `PATCH /kitchen/items/{item_id}/status`(updateKitchenItemStatus).
- 경과 시간은 `created_at`에서 클라이언트가 계산한다.
- 목록: `GET /kitchen/queue`(pending·cooking 항목만 돌려준다). 갱신은 5초 폴링이다(D-30). SSE는 2차.
- 항목 처리 응답 본문은 계약에 없으므로 쓰지 않고, 처리 후 다시 조회해서 확인한다(B-16에서 계약 보완 예정).

## 대비
본문 `--color-text-primary` on 흰색 16.1:1, "지연" `--color-warning-text` on `--color-warning-light` 7.41:1, 흰 글자 on 버튼 5.13~5.75:1. 직접 계산한 값이며 도구 검증 전.

## 완료 조건 (구현자, U-04 상세 명세 전 잠정)
1. 메뉴명·수량 글자 59px 이상, 버튼 높이 88px 이상.
2. 상태는 색 + 아이콘 + 글자.
3. 토큰 변수만 사용. 하드코딩 색 없음.

# U-04 상세

## 결정 1. 버튼은 항목 단위 + 카드 일괄 버튼
주방은 `PATCH /orders/{id}/status`를 쓸 수 없고 `PATCH /kitchen/items/{item_id}/status`(pending/cooking/done)만 쓴다. 주문 상태는 서버가 항목 상태로 자동 계산한다.
- 항목 행마다 버튼 하나: `pending` → "시작"(primary), `cooking` → "완료"(success). `done`이면 버튼 대신 "완료"(아이콘 + 글자)와 흐린 이름.
- 카드 하단 일괄 버튼은 같은 상태 항목이 2개 이상일 때만 나온다: 접수 레인 "전부 시작", 조리 중 레인 "전부 완료"(secondary). 프론트가 항목 PATCH를 항목 수만큼 호출한다.
- 레인(접수/조리 중)은 서버가 계산한 주문 상태 기준이다. 항목이 하나라도 `cooking`이면 주문은 조리 중 레인으로 옮겨진다.
- 이유: 한 요리가 먼저 나가는 일이 흔하고, 일괄만 있으면 먼저 끝난 요리를 표시할 수 없다. 일괄 버튼은 손이 바쁠 때 탭 수를 줄인다.

## 결정 2. 부분 실패
일괄 처리 중 일부 항목만 실패하면 성공한 항목은 그대로 두고 실패한 항목 행만 빨간 "다시 시도"(경고 아이콘 + 글자) 버튼으로 바꾼다. 화면 상단에 `role="alert"` 배너로 "7번 테이블: 3개 중 1개를 처리하지 못했습니다 / 제육볶음만 다시 시도해 주세요. 나머지 2개는 처리됐습니다."를 남긴다. 배너는 자동으로 사라지지 않고 다시 시도가 성공하면 닫힌다.

## 결정 3. 테마
주방 다크 팔레트(#111, #222)는 1차에서 쓰지 않고 다른 화면과 같은 밝은 테마로 통일한다(D-38 다크 모드 제외, 토큰 단일화). 근거: 토큰을 하나로 유지하는 것이 1차 범위에 맞고, 밝은 테마 본문 대비는 16.1:1(직접 계산)이다. 주방 조명 환경은 확인하지 못했다. 현장 테스트에서 눈부심 의견이 나오면 2차에서 토큰으로 다크 테마를 추가한다. 정주현 님 확인 필요.

## 상태 정의
- **기본:** 두 레인과 카드. 접수 10분 이상(제안) 카드는 주황 테두리 + "지연" 배지.
- **로딩:** "주문을 불러오는 중"(스피너 + 글자) + 회색 스켈레톤 카드. 상단 연결 표시는 "연결 중". 버튼 없음.
- **빈 상태:** 수저 아이콘 + "지금 들어온 주문이 없습니다" + "새 주문이 들어오면 이 화면에 바로 나타납니다." 레인 하나만 비었을 때는 레인 안에 "접수된 주문이 없습니다" / "조리 중인 주문이 없습니다".
- **오류(불러오기 실패):** 경고 아이콘 + "주문을 불러오지 못했습니다" + "네트워크를 확인하고 다시 시도해 주세요." + "다시 시도" 버튼(88px). 상단 표시 "연결 안 됨"(빨강, 아이콘 + 글자).
- **연결 끊김(폴링 실패):** 마지막 데이터는 그대로 두고 경고 배너 "연결이 끊겼습니다. 다시 연결하는 중입니다." + "아래 주문은 18:41 기준이며 새 주문이 보이지 않을 수 있습니다. 버튼은 연결될 때까지 쓸 수 없습니다." + "지금 다시 연결". 모든 버튼 비활성(`disabled`). 잘못된 시각 표시를 막기 위해 시각은 마지막 수신 시각을 쓴다.
- **처리 중(비활성):** 누른 항목 버튼은 스피너 + "처리 중"으로 비활성, 같은 카드 일괄 버튼도 비활성. 다른 카드는 계속 누를 수 있다. 응답이 오면 즉시 복구.
- **일부 항목 실패:** 위 결정 2.
- **긴 메뉴명:** 2줄까지 표시 후 말줄임(`word-break: keep-all`). 일반 텍스트로만 렌더링(D-24).

## 항목 행 크기
행 최소 높이 88px(`--size-touch-kitchen`), 이름·수량 59px, 버튼 폭 176px 이상. 카드 한 장이 3항목일 때 약 360px라 1080p에서 레인당 2~3장이 한 화면에 보인다. 더 많으면 레인 안에서 세로 스크롤하고 헤더(건수)는 고정한다.

## 동선·접근성
- 터치 영역 88px, 버튼 사이 간격 8px 이상(오터치 방지).
- 포커스 링은 공통 토큰(2px). 키보드·마우스 보조 사용 시 Tab 순서는 카드 순서대로.
- 연결 상태, 경고, 실패 배너는 `role="status"` 또는 `role="alert"`.
- 상태는 항상 색 + 아이콘 + 글자.

## 계약 확인 결과 (민준 님 답변, 백엔드 코드 확인)
1. 일괄 처리는 항목 PATCH를 동시에 호출해도 된다(`Promise.allSettled`). 항목마다 별도 트랜잭션이고 주문 상태는 `received→cooking` 한 방향으로만 자동 변경돼 결과가 같다.
2. 같은 상태로 다시 보내도 200이다(멱등). 재시도는 안전하다.
3. 실제 응답은 `{item_id, status}`이고 404·409도 실제로 온다. 계약에는 이 셋이 없다. **B-16에서 계약 보완 예정**이며 그 전까지 프론트는 응답 본문을 쓰지 않고 다시 조회한다.
4. `GET /kitchen/queue`는 pending·cooking 항목만 돌려준다.

## 완료 항목 표시와 queue 한계
`/kitchen/queue`는 `done` 항목을 돌려주지 않는다. 그래서 "완료" 표시(체크 + 흐린 이름)는 방금 완료를 누른 항목만 다음 폴링 전까지 화면에 남기는 임시 표시이고, 다음 폴링에서 행이 사라진다. 한 주문의 일부만 끝난 상태를 계속 보여 줘야 하면 queue가 같은 주문의 done 항목도 주는지 계약 확인이 필요하다(B-16에서 함께 확인 요청).

## 실패 표시 해제 규칙
실패한 항목 행의 "다시 시도" 표시는 다음 폴링(5초) 응답에서 아래 중 하나가 되면 지운다. 응답이 유실됐지만 서버는 처리한 경우를 포함한다.
1. 그 항목의 상태가 목표 상태로 바뀌어 있을 때
2. 목표 상태가 `done`이고 그 항목이 목록에서 사라졌을 때(queue는 done을 주지 않는다)
사용자가 "다시 시도"를 눌러 성공해도 같은 방식으로 해제한다. 상단 부분 실패 배너는 해당 카드의 실패 행이 모두 없어지면 닫는다.

## 열린 항목 (정주현 님)
- 주방 모니터 크기(인치)와 해상도. 현재 값은 1920×1080 가정이며 크기가 작으면 59px 본문 기준을 다시 잡는다.
- "지연" 기준 분(제안 10분).
- 밝은 테마 통일(결정 3) 확인.

## 완료 조건 (구현자)
1. 항목 단위 버튼과 일괄 버튼이 위 규칙대로 동작하고, 일괄 처리의 부분 실패에서 성공 항목은 유지된다. 실패 표시는 위 해제 규칙으로 지운다.
2. 연결 끊김에서 모든 버튼이 `disabled`이고 배너가 보인다.
3. 메뉴명 59px 이상, 버튼 88px 이상, 토큰 변수만 사용(하드코딩 색 없음).
4. 지연 기준 분은 상수 하나로 둔다.
5. 상태별 캡처: `screens/u04-kitchen-{default,loading,empty,error,offline,busy,partial}.png`
