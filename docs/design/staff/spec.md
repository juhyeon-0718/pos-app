# U-05 직원 화면 명세

상태: 메인 화면(U-03) + 상태별 시안·상세(U-05). 기준 기기: 태블릿 가로 1024×768.
프로토타입: `prototype/staff.html`(메인), `prototype/staff-states.html`(상태 보기 바 또는 `?state=default|loading|empty|error|offline|busy|conflict|stock|cancel|cancel-locked|pay|proxy|proxy-409`).

## 구성
- 상단 바: 로고, 화면 이름, 연결 상태("연결됨"), "대리 주문"(primary, 56px).
- 필터 칩: 전체 / 접수 / 조리 중 / 서빙 완료. 칩마다 건수(숫자 배지). 결제 완료·취소는 기본으로 숨김.
- 주문 카드(2열): 테이블 번호, 상태 배지(큰), 항목·수량, 접수 시각·경과, 합계, 액션 버튼(56px).
- 액션은 상태별 한 개: 접수 → "주문 취소"(text danger, 확인 모달), 조리 중 → "서빙 완료"(success, 모든 항목 `item_status=done`일 때만 활성. 비활성이면 이유를 글자로 안내), 서빙 완료 → "결제 완료"(primary).
- 지금 눌러야 할 카드(서빙 가능, 결제 대기)는 `--color-primary` 2px 테두리로 구분한다.

## 사용 토큰
`--size-touch-lg`, `--font-size-3xl/xl/lg`, `--color-primary`, 공용 Badge(주문 상태 5종), Button, Card(U-03 components).

## 데이터 (openapi.yaml 기준)
Order: `id`, `table_no`, `status`, `total_amount`, `created_at`, `items[]`(`menu_name`, `qty`, `item_status`), `stock_warnings[]`(직원·사장용). 상태 변경은 `PATCH /orders/{order_id}/status`(received→cooking→served→paid, cancelled).

## 계약 요청
없음. `table_no`는 계약에 이미 있다. 대리 주문 화면의 테이블 선택(`GET /tables`)과 `stock_warnings[]` 표시 위치(카드 배너)는 U-05 상세 명세에서 정한다.

## 대비
상태 배지 대비는 `../components/spec.md`. 칩 선택 상태는 `--color-primary` on `--color-info-light` 5.03:1. 직접 계산한 값이며 도구 검증 전.

## 완료 조건 (구현자, 잠정)
1. 모든 버튼 높이 56px 이상, 칩 56px 이상.
2. 취소는 확인 모달을 거친다. 결제·서빙은 한 번 눌러 처리하고 실패하면 카드 안에 오류 배너.
3. 토큰 변수만 사용.

# U-05 상세

## 갱신 방식
`GET /orders`는 `status`를 하나만 받으므로 5초마다 `received`, `cooking`, `served`를 병렬로 3번 호출해 합치고 칩 건수를 센다(계약 변경 없음). 일부 호출만 실패하면 마지막 성공 데이터를 유지하고 "연결 끊김" 상태로 처리한다. (D-30, 주방과 같은 폴링) 필터 칩 옆에 "18:42 갱신 · 5초마다 자동"을 둔다. 처리 버튼을 누르면 응답 후 바로 다시 조회한다. 폴링 간격은 상수 하나.

## 액션 규칙 (권한은 openapi `PATCH /orders/{id}/status` 기준)
- 접수(`received`): "주문 취소"만. 확인 모달을 거친다. 직원은 조리 시작 전 주문만 취소할 수 있다.
- 조리 중(`cooking`): "서빙 완료". 모든 항목이 `done`일 때만 활성(D-32). 직원에게는 취소 버튼을 보여 주지 않는다(조리 후 취소는 사장 전용).
- 서빙 완료(`served`): "결제 완료". 확인 모달을 거친다(결제 후에는 상태를 바꿀 수 없다).
- 결제 완료·취소: 기본 목록에서 숨긴다.

## 상태 정의
- **기본:** 2열 카드. 서빙 가능·결제 대기 카드는 primary 2px 테두리.
- **로딩:** "주문을 불러오는 중"(스피너 + 글자) + 회색 스켈레톤 카드 4장. 연결 표시 "연결 중". 대리 주문 버튼 비활성.
- **빈 상태:** 받은 편지함 아이콘 + "처리할 주문이 없습니다" + "새 주문이 들어오면 이 화면에 나타납니다. 직접 넣을 주문은 오른쪽 위 \"대리 주문\"으로 넣을 수 있습니다." 칩 건수 0.
- **오류(불러오기 실패):** 경고 아이콘 + "주문을 불러오지 못했습니다" + "네트워크를 확인하고 다시 시도해 주세요." + "다시 시도". 연결 표시 "연결 안 됨"(아이콘 + 글자). 대리 주문 비활성.
- **연결 끊김(폴링 실패):** 마지막 데이터를 유지하고 경고 배너 "연결이 끊겼습니다. 다시 연결하는 중입니다." + "아래 주문은 18:41 기준이며 새 주문이 보이지 않을 수 있습니다. 처리 버튼은 연결될 때까지 쓸 수 없습니다." + "지금 다시 연결". 모든 처리 버튼과 대리 주문 비활성, 갱신 시각은 "18:41 기준".
- **처리 중(비활성):** 누른 카드의 버튼만 스피너 + "처리 중"으로 비활성. 다른 카드는 계속 누를 수 있다.
- **"서빙 완료" 비활성 문구(지호 님 지적 반영):**
  - 항목이 아직 안 끝났을 때: 버튼 왼쪽에 "조리가 끝나면 누를 수 있습니다"(정보 아이콘 + 글자).
  - 연결이 끊겼을 때: "연결이 복구되면 누를 수 있습니다".
  - 주방이 방금 완료했는데 아직 비활성이면 최대 5초 안에 갱신된다. 별도 문구는 두지 않고 갱신 시각 표시로 알린다.
- **409 서빙 불가(`ORDER_ITEMS_NOT_DONE`):** 카드 안 `role="alert"` 배너 "아직 서빙 완료로 바꿀 수 없습니다 / 조리가 끝나지 않은 항목이 있습니다. 화면을 새로 불러왔습니다." 응답 후 즉시 재조회한다.
- **그 밖의 409(예: 다른 직원이 방금 취소·결제함):** 같은 카드 안 배너 "주문 상태가 바뀌어 처리하지 못했습니다 / 화면을 새로 불러왔습니다." 후 재조회한다. `ORDER_ITEMS_NOT_DONE`은 위 전용 문구.
- **403 취소 불가:** 화면이 최신이 아닐 때(그 사이 조리가 시작됨) 접수 카드의 취소가 403이면 카드 안 배너 "취소하지 못했습니다 / 그 사이 조리가 시작되어 사장님만 취소할 수 있습니다. 화면을 새로 불러왔습니다." 후 재조회.
- **재고 부족 경고(`stock_warnings[]`):** 해당 카드 안 경고 배너(경고 아이콘 + 글자) "재고가 부족한 재료가 있습니다: {재료명}. 주문은 접수됐습니다. 사장님께 알려 주세요." 주문 생성은 막지 않는다(D-14). 파일럿에서는 D-34로 값이 항상 비어 있어 나타나지 않는다. 재료명은 일반 텍스트로만 표시하고 길면 말줄임(D-24).
- **취소 확인 모달:** 제목 "{n}번 테이블 주문을 취소할까요?", 본문 "접수된 주문 {금액}원이 취소됩니다. 취소한 주문은 되돌릴 수 없습니다." 버튼 "돌아가기"(secondary) / "주문 취소"(danger). 처리 중에는 둘 다 비활성, Esc 비활성.
- **결제 확인 모달:** 제목 "{n}번 테이블 결제를 완료할까요?", 본문 "합계 {금액}원을 받으셨는지 확인해 주세요. 결제 완료 후에는 상태를 바꿀 수 없습니다." 버튼 "돌아가기" / "결제 완료"(primary).
- **대리 주문 모달:** 테이블 번호 버튼 격자(`GET /tables`의 `table_no`, 각 56px), 메뉴 행(이름·가격·수량 − + 56px), 합계, "{n}번 테이블 주문 넣기"(테이블 미선택·수량 0이면 비활성). 요청은 `table_id`와 `items[{menu_id, qty}]`, `Idempotency-Key`(클라이언트 UUID, 모달을 열 때 생성, 재시도 시 같은 값). `code=IDEMPOTENCY_KEY_MISMATCH`인 422만 모달 안 배너 "주문 내용이 바뀌어 다시 보내야 합니다. 닫고 다시 시작해 주세요."로 보이고, 그 밖의 422(테이블 누락·검증 실패)는 "주문을 넣지 못했습니다. 입력을 확인해 주세요." 배너로 보인다. 409 `MENU_UNAVAILABLE`(모달을 연 뒤 메뉴가 일시 품절됨)은 모달 안 배너 "{메뉴명}은(는) 방금 품절되어 주문할 수 없습니다. 메뉴를 새로 불러왔습니다."를 보이고 `GET /menus`를 다시 조회한 뒤 해당 메뉴를 목록에서 뺀다. 이때 주문은 만들어지지 않았으므로 다음 전송은 새 `Idempotency-Key`를 쓴다 성공 시 모달을 닫고 토스트 "{n}번 테이블 주문이 접수됐습니다".
- **긴 메뉴명:** 줄바꿈하고 카드 높이만 늘어난다. 일반 텍스트로만 표시.

## 대리 주문에서 표시하는 메뉴
`GET /menus` 결과에서 `is_active=true`인 메뉴만 보인다(D-37: 일시 품절은 숨김). 수량 최대값은 계약에 없다. 제안 20(메뉴당), 확정은 민준 님 확인 후.

## 터치·접근성
- 모든 버튼·칩·테이블 격자·수량 버튼 56px 이상(최소 44px 규칙 충족), 카드 사이 간격 16px.
- 모달은 포커스를 가두고 Esc로 닫으며 닫은 뒤 열었던 버튼으로 돌아간다(처리 중 제외).
- 상태는 색 + 아이콘 + 글자. 오류는 배너(`role="alert"`)로 남기고 자동으로 사라지지 않는다. 성공 토스트만 자동으로 사라진다.

## 계약 요청 (민준 님께, 계약은 직접 수정하지 않음)
1. (필수 아님) `GET /orders`가 여러 `status`를 받거나 "진행 중 주문" 조회가 있으면 호출 3회를 1회로 줄일 수 있다. 지금은 3회 병렬 호출로 구현 가능하다.
2. 대리 주문 수량 최대값 계약 없음(위 제안 20).
3. **결정 필요(F-11 범위 영향):** `GET /tables`는 계약상 사장 전용(403)이라 직원 토큰으로 대리 주문의 테이블을 고를 수 없다. 대리 주문 요청은 `table_id`가 필요하고 화면은 `table_no`를 보여 주므로 (a) 직원에게 `GET /tables` 조회를 열거나 (b) 직원용 테이블 목록 조회를 추가해야 한다. 번호 직접 입력은 `table_no`→`table_id` 변환이 없어 불가능하다. 디자인은 (a)/(b) 어느 쪽이든 같은 테이블 번호 격자다.

## 완료 조건 (구현자)
1. 위 액션 규칙과 권한 규칙대로 버튼이 나온다. 직원에게 조리 중 주문의 취소는 보이지 않는다.
2. "서빙 완료"는 모든 항목이 `done`일 때만 활성이고, 비활성 이유가 글자로 보인다.
3. 취소·결제는 확인 모달을 거친다. 409·403은 카드 안 배너 + 재조회.
4. 연결 끊김에서 모든 처리 버튼이 `disabled`이고 마지막 갱신 시각이 보인다.
5. 폴링 간격(5초)은 상수 하나. 모든 버튼 56px 이상. 토큰 변수만 사용.
6. 상태별 캡처: `screens/u05-staff-{default,loading,empty,error,offline,busy,conflict,stock,cancel,cancel-locked,pay,proxy,proxy-409}.png`
