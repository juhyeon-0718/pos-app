# U-06 손님 QR 주문 화면 명세

상태: 메뉴 목록 메인(U-03) + 흐름 4화면 상태별 시안·상세(U-06).
프로토타입: `prototype/customer.html`(메인), `prototype/customer-flow.html`(상태 보기 바 또는 `?state=` 키 18종, 390×844). 기준 기기: 손님 휴대폰, 한 손 조작.

## 구성
- 상단 바: 로고, 테이블 번호 배지, 탭(메뉴 / 주문 내역, 높이 48px).
- 카테고리 칩(가로 스크롤, 높이 44px). 카테고리는 `Menu.category`.
- 메뉴 행 카드: 이름(2줄 말줄임), 가격, 오른쪽에 "담기" 버튼 또는 수량 조절(− 수량 +, 각 44px). 담으면 수량 조절로 바뀐다.
- 하단 고정 바: "장바구니 보기" + 담은 개수 + 합계. 장바구니가 비면 비활성.
- 엄지 영역(화면 아래쪽)에 주 행동을 둔다. 메뉴 이름은 일반 텍스트로만 표시한다.

## 사용 토큰
`--size-phone-max`, `--size-touch-lg`(하단 바 52px 이상), `--size-touch-min`, `--color-primary`, 공용 Button·Card·Badge(U-03 components).

## 데이터 (openapi.yaml 기준)
- Menu: `id`, `name`, `price`, `category`, `is_active`. 목록은 `GET /menus`(tableToken).
- 주문 생성 본문은 `items[{menu_id, qty}]`만 보낸다. 세션은 `POST /tables/{table_id}/session`.

## 계약 요청·결정 반영
1. 테이블 번호: 세션 응답에 `table_no`가 없다. 10/24에 B-14로 추가 예정(민준 님). 그 전까지 시안의 "3번 테이블"은 더미이고, 구현은 B-14 이후에 붙인다.
2. 일시 품절(D-37): 손님 메뉴판에서 숨긴다. 품절 표시는 두지 않는다(시안에도 없음).
3. `stock_warnings[]`: 손님 화면에는 표시하지 않는다. 10/24 B-15에서 손님 응답 정리 예정. 파일럿 중에는 D-34로 값이 항상 비어 있다.
4. 메뉴 이미지·설명 필드는 없다. 이번 시안은 이름·가격만 쓴다.

## 대비
`--color-text-secondary` on 흰색 5.74:1(가격), `--color-primary` on `--color-info-light` 5.03:1(선택 칩), 흰 글자 on primary 5.75:1. 직접 계산한 값이며 도구 검증 전.

## 완료 조건 (구현자, 잠정)
1. 320px 폭에서 가로 스크롤 없이 동작(카테고리 칩 제외).
2. 모든 터치 요소 44px 이상. 하단 바에 안전 영역(`env(safe-area-inset-bottom)`) 반영.
3. 토큰 변수만 사용.

# U-06 상세

## 흐름
메뉴 → 장바구니 → 주문 확인(아래 시트) → 주문 완료 → 주문 내역(상태). 탭은 "메뉴 / 주문 내역" 두 개. 장바구니는 메뉴 위에 올라오는 화면(왼쪽 위 ✕로 닫기), 주문 확인은 아래에서 올라오는 시트.

## 더미 메뉴 (정주현 님 허락, 공개 저장소 시안용)
오늘의 플레이트 15,000(메인) / 마른안주·올리브마리네이트·치즈 플레이트·버팔로 윙 각 10,000, 참치마요 카나페 4,000(사이드). 주류는 판매가가 정해지지 않아 시안에서는 이름에 "(더미)"를 붙인 2종(생맥주 500cc 5,000, 하이볼 6,000)으로 카테고리 칩이 늘어나는 모양만 보여 준다. 실제 가격이 아니다. 카테고리 표시 이름은 `Menu.category` 값을 프론트 매핑 테이블로 한글로 바꾼다(D-18과 같은 방식). 매핑에 없는 값은 값 그대로 보인다.

## 상태 정의
**메뉴**
- 기본: 카테고리 칩(가로 스크롤) + 카테고리별 섹션. 담으면 "담기"가 수량 조절(− 수량 +)로 바뀐다. 하단 바 "장바구니 보기 {개수} {합계}".
- 로딩: "메뉴를 불러오는 중" + 스켈레톤 4줄. 하단 바 비활성.
- 빈 상태: 수저 아이콘 + "지금 주문할 수 있는 메뉴가 없습니다" + "직원에게 말씀해 주세요." 하단 바 비활성.
- 오류: 경고 아이콘 + "메뉴를 불러오지 못했습니다" + "네트워크를 확인하고 다시 시도해 주세요." + "다시 시도". 하단 바 비활성.
- 세션 만료(401, `table_session_token` 만료 4시간·QR 재발급): 자물쇠 아이콘 + "주문 시간이 지났습니다" + "테이블의 QR 코드를 다시 찍어 주세요. 계속 안 되면 직원에게 말씀해 주세요." 버튼 없음(QR은 기기 밖에서 찍는다). 담아 둔 장바구니는 새 세션에서 비운다.

**장바구니**
- 기본: 행마다 이름(3줄 말줄임)·단가·수량 조절·행 합계, 합계 카드, 안내 "주문을 보낸 뒤에는 직원에게 말씀해야 취소할 수 있습니다." 하단 바 "주문하기 {합계}".
- 빈 상태: 장바구니 아이콘 + "담은 메뉴가 없습니다" + "메뉴에서 먹고 싶은 것을 담아 주세요." + "메뉴 보기". "주문하기" 비활성.
- 수량 20 제한: 메뉴당 20개(직원 대리 주문과 같은 화면 제한, 계약은 바꾸지 않음). 20에서 "+"는 비활성, 행에 "최대 20개까지 담을 수 있습니다"를 글자로 보인다. 수량을 0으로 줄이면 행이 사라진다.

**주문 확인(시트)**
- 기본: 제목 "주문을 보낼까요?", 테이블·개수, 항목·수량·금액, 합계, "주문 보내기"(primary)와 "돌아가기". 버튼은 세로로 쌓고 각 52px 이상.
- 전송 중: 두 버튼 모두 비활성, "보내는 중"(스피너 + 글자). Esc·바깥 터치로 닫히지 않는다.
- 전송 실패(네트워크·5xx): 시트 안 `role="alert"` 배너 "주문을 보내지 못했습니다 / 네트워크를 확인하고 다시 눌러 주세요. 주문이 두 번 들어가지 않습니다." 버튼 "다시 보내기". 재시도는 같은 `Idempotency-Key`를 쓴다(키는 시트를 열 때 생성). 장바구니 내용이 바뀌면 새 키.
- 메뉴 품절(409 `MENU_UNAVAILABLE`): 배너 "{메뉴명}은(는) 방금 품절되었습니다 / 장바구니에서 뺐습니다. 나머지 메뉴로 다시 확인해 주세요." 해당 메뉴를 장바구니에서 빼고 `GET /menus`를 다시 조회한다. 버튼 "장바구니로 돌아가기". 주문이 만들어지지 않았으므로 다음 전송은 새 키. 메뉴명은 응답 `detail`에서 읽지 않고 장바구니와 다시 불러온 메뉴를 대조해 정한다(일반 텍스트로만 표시, D-24).
- 그 밖의 422(`IDEMPOTENCY_KEY_MISMATCH`): 위 전송 실패 배너와 같은 문구에 "다시 보내기"가 새 키로 보낸다.

**주문 완료:** 체크 아이콘 + "주문이 접수되었습니다" + "조리가 시작되면 \"주문 내역\"에서 진행 상태를 볼 수 있습니다." 버튼 "주문 내역 보기"(primary), "더 주문하기". `stock_warnings`는 응답에 있어도 표시하지 않는다.

**주문 내역(`GET /orders/mine`, 10초 폴링, D-17)**
- 기본: 갱신 안내 "18:42 기준 · 10초마다 자동 갱신". 주문별 카드: 큰 상태 배지 + 접수 시각, 3단계 진행 막대(접수 → 조리 중 → 서빙 완료, 지난 단계는 체크 + 굵게, 현재 단계는 primary 굵게), 항목·수량·항목 상태(대기/조리 중/조리 완료), 합계. 최신 주문이 위.
- 로딩: "주문 내역을 불러오는 중" + 스켈레톤.
- 빈 상태: 영수증 아이콘 + "아직 주문 내역이 없습니다" + "메뉴에서 주문하면 여기에서 진행 상태를 볼 수 있습니다." + "메뉴 보기".
- 오류(폴링 실패): 마지막 데이터를 유지하고 경고 배너 "주문 내역을 새로 불러오지 못했습니다 / 마지막으로 본 내용을 보여 드립니다. 10초마다 다시 시도합니다." + "지금 다시", 갱신 시각은 "18:41 기준".
- 결제 완료: 진행 막대 없이 "결제 완료" 배지. 취소: "취소" 배지 + "직원이 주문을 취소했습니다. 궁금한 점은 직원에게 말씀해 주세요."

## 문구 원칙
손님에게는 "항목 취소"나 "재고" 같은 내부 말을 쓰지 않는다. 취소는 직원에게 말하도록 안내한다(손님 취소 API 없음). 모든 오류는 무엇이 일어났는지 + 다음에 할 일을 한 문장씩.

## 접근성·한 손 조작
- 터치 영역: 수량 버튼 44px, 담기·카테고리 칩 44px, 하단 바 52px, 시트 버튼 52px, 탭 48px.
- 하단 바와 시트는 `env(safe-area-inset-bottom)`을 더한다. 주요 행동(담기, 주문하기, 주문 보내기)은 화면 아래쪽에 둔다.
- 수량 변화는 `aria-live="polite"`, 오류는 `role="alert"`, 시트는 포커스를 가두고 닫으면 열었던 버튼으로 복귀(전송 중 제외).
- 상태는 색 + 아이콘 + 글자. 320px 폭에서도 가로 스크롤은 카테고리 칩에만 있다.

## 계약 확인이 필요한 점 (민준 님께)
1. `GET /orders/mine`이 취소·결제 완료 주문도 돌려주는지, 몇 건까지 주는지(페이지 없음). 테이블 세션 안의 주문만이라면 시안처럼 모두 보인다.
2. 401(세션 만료)은 `GET /menus`와 `POST /orders` 모두에서 같은 형식인지.
3. 주류 26종이 올라가면 메뉴 수가 30개를 넘는다. `GET /menus`는 `limit`·`cursor` 페이지를 쓰므로 손님 화면은 전체를 불러온 뒤 카테고리로 나눈다. 한 번에 최대 몇 개를 주는지 확인이 필요하다.

## 완료 조건 (구현자)
1. 위 18개 상태가 시안과 같은 문구·구조로 나온다. 캡처: `screens/u06-customer-{menu,menu-loading,menu-empty,menu-error,session,cart,cart-empty,cart-max,confirm,submitting,submit-error,submit-409,done,status,status-loading,status-empty,status-error,status-end}.png`
2. `Idempotency-Key`는 시트를 열 때 만들고 재시도에 같은 값을 쓴다. 장바구니가 바뀌거나 409 뒤에는 새 값.
3. 전송 중에는 중복 전송이 불가능하다(버튼 비활성).
4. 메뉴명·재료명 등 모든 문자열은 일반 텍스트로 렌더링한다(D-24).
5. 주문 내역 폴링 간격 10초는 상수 하나.
6. 모든 터치 요소 44px 이상, 토큰 변수만 사용.
