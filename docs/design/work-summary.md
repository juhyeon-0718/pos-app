## 2. U-01 사장 관리 화면

- 화면 3개: 메뉴 관리 `/admin/menus`, 식재료 관리 `/admin/ingredients`, 레시피 편집 `/admin/menus/:menu_id/recipe`(2차, D-34).
- 화면마다 기본·로딩·빈 상태·조회 오류·저장 중·저장 실패(409/422)·삭제 확인·삭제 실패·사용중지 항목을 정의했다.
- 명세 구성: 범위·원칙·용어집 → 공통 상태 규칙 → 화면별 구성·상태·폼 필드 표·확인 모달 문구 → 접근성 검사(텍스트 대비, UI 대비, 터치 영역, 키보드·낭독) → API 응답별 문구 → 공용 컴포넌트(토큰 이름) → 필드 검증표(openapi 대조) → 계약 요청 → 구현 완료 조건 → 프로토타입 상태 목록.
- 프로토타입: 정적 HTML 3장 + `admin.css` + `admin.js`. 더미 데이터만, 외부 에셋 없음. 상단 "상태 보기" 바와 `?state=<키>`로 모든 상태를 바로 연다. 예: `menus.html?state=m-409`.
- 원칙: 상태는 색+아이콘+텍스트, 오류는 `role=alert` 배너, 이름은 평문 렌더링과 길이 제한(D-24), 목록은 "더 보기"(이전 페이지 없음), 삭제 문구는 계약의 실제 동작(비활성화, 복구 가능)대로 쓴다.

## 3. 디자인 토큰 (DESIGN.md)

- 색, 타이포, 간격, 크기, 모서리, 그림자, 경계선, 접근성, 반응형, 폰트 스택을 정의했다.
- 대비 오류를 고쳤다: `--color-text-disabled` #cccccc(1.61:1) → #767676(3.91:1). `--color-warning`은 글자색으로 쓸 수 없다(2.65:1). `--color-border-default`는 UI 경계로 쓰지 않는다(1.54:1).
- 추가한 토큰: `--color-border-strong`, `--color-bg-disabled`, `--color-error-hover`, `--color-warning-text`, `--color-text-on-fill`, `--color-focus-ring`, `--color-overlay`, `--size-*`. 폰트 스택에 Malgun Gothic을 추가했다.
- 기존 로그인·손님·주방·직원 화면의 토큰 적용 여부는 점검하지 않았다. 후속 U-xx 대상이다.

## 4. U-01b 일시품절·삭제 분리 (D-37)

- 메뉴 화면에서 "일시품절(판매 중지/재개)"과 "삭제"를 별도 동작으로 나눴다. 명세 §2와 `menus.html` 프로토타입을 고쳤다.
- 확인 필요: 로컬 `docs/decisions.md`에는 D-37이 아직 없다(main 반영 전). 문구는 PR #23 기준이다.

## 5. U-02 브랜드 로고

- 로고 원본은 정주현이 저장소 반영을 승인했다. 출처와 라이선스는 `assets-license.md`에 기록했다(상표성 자산, 저장소 라이선스와 별개).
- 사용 규칙(`DESIGN.md` 브랜드 절): LIVE PUB 항상 표시, 최소 크기, 배경별 흑백 선택(검정 로고는 `--color-primary` 위에서 3.65:1이라 금지), 여백 25%, alt 문구, 화면별 배치.
- 사장 상단 바에 축약형 로고를 적용했다. 대비·소형 크기 확인용 `brand/logo-preview.html`을 만들었다.
- **미커밋 작업 중**: 파생 파일명을 `compact` → `stacked`/`sm`으로 정리하는 변경이 워킹트리에 있다(`logo-stacked-*.png`, `logo-sm-*.png` 추가, 기존 `compact`·`white-sm`·`black-sm` 삭제). 이 변경은 아직 검수하지 않았고 `DESIGN.md`·`admin.css`·`admin.js`의 파일 참조도 맞추지 않았다. 완료 전까지 커밋하지 않는다.
- 축약형은 원본 재배치 파생 파일이라 정주현이 모양을 확인하기 전까지 시안이다.

## 6. 민준에게 요청 중인 계약 사항 (`admin-spec.md` §9)

계약(`openapi.yaml`)은 수정하지 않았다. 요약:
1. 목록이 비활성 항목을 포함하는지. 2. POST/PATCH/PUT의 409·422·404 선언과 `Error.code` 목록. 3. PATCH가 전체 본문을 요구하는지. 4. 값 제약(길이, 최솟값). 5. 레시피 화면의 메뉴 이름(단건 GET 또는 `menu_name`). 6. 식재료 삭제 409에 사용 중인 메뉴 정보. 7. `RecipeItem.unit` 채우는 주체. 8. 초기 재고·재고 보정 화면 범위(정주현·민준 결정 필요). 9. 빈 레시피·중복 항목 처리. 10. (선택) 메뉴 목록 `has_recipe`.

## 7. 검증 상태 (확인한 것과 못 한 것)

- 대비율은 손계산이다. 도구로 돌리지 않았다.
- 터치 44px은 CSS 설계값이다. 실기기 측정은 아직 없다.
- 프로토타입은 이 명세서 작성 중 브라우저로 열어보지 않았다. 구현(F-06)은 박지호가 10/20에 완료했다.
- axe 검사는 구현 완료 조건으로 박지호에게 넘겼고, 디자인 쪽에서는 돌리지 않았다.
